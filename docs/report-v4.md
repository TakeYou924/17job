# 업무환경 해설지 v4 구현

## 위치와 범위
결과 화면의 ‘부담으로 표시한 환경’ 태그 바로 아래에 독립적인 해설지를 삽입했습니다. 원본 17문항과 기존 직무체험 데이터·미션·피드백은 변경하지 않았습니다. 새 직무체험이나 AI API 호출을 추가하지 않았습니다.

## 해석 원칙
- A/B: 상대적으로 더 어렵다고 선택한 환경. 절대적 부적합이나 반대 환경의 선호·능력으로 바꾸지 않습니다.
- C(기존 앱의 both): 두 환경 모두 감당 가능하다는 응답. 강점·높은 적응력·직업 적합성을 만들지 않습니다.
- 모든 개별 해설은 확인된 응답, 실제 업무 장면, 추가로 살펴볼 조건으로 분리하고 원본 선택을 근거로 확인할 수 있습니다.
- 보상·시간·안정·성장 등 복수 가치가 결합된 문항은 가치관으로 단정하지 않습니다.

## 데이터와 선택 규칙
- `src/data/report.json`: 34개 A/B 해설, 5개 영역, P01~P05 조합, 일반 확인 질문, 한계 안내.
- `src/lib/report.ts`: 사용자 응답에서 실제 선택된 조건만 추출하는 순수 생성 함수.
- 모든 요구 응답이 정확히 일치한 조합만 활성화합니다.
- 핵심 카드는 조합을 우선해 최대 3개 선택합니다. 가능한 한 다른 영역을 포함하고, 같은 근거를 공유하는 조합을 중복 노출하지 않습니다.
- 남는 유효 조합 중 핵심과 근거가 겹치지 않는 항목을 최대 2개 추가합니다. 남은 개별 조건은 영역 상세에서 확인할 수 있습니다.
- 선택 순서는 규칙·문항 순서와 영역 분산을 위한 편집 규칙이며 심리적 중요도 순위가 아닙니다.
- 카드가 1~2개면 그만큼만 표시합니다. 전체 C에서는 부담 카드나 강점을 생성하지 않고 일반 체크리스트임을 명시합니다.
- 상세 영역은 핵심에서 이미 설명한 조건을 다시 길게 복사하지 않고 보충 조건을 우선합니다. 구체적인 업무 장면과 탐색 방식은 핵심 설명과 다른 문장으로 제공합니다.

## UI와 출력
- `src/components/report/report-view.tsx`: 헤더, 핵심, 주의/탐색 업무, 5개 영역, 유효 추가 조합, 체크리스트, 원본 응답, 인쇄.
- 색상은 주의와 탐색을 구분하며 합격·불합격 판정에 사용하지 않습니다.
- 원본 응답과 근거는 해설지 내부의 접근 가능한 details/summary로 제공합니다. 기본 결과의 모든 부담 태그는 유지됩니다.
- 기존 기록에 완료 날짜가 없으면 ‘완료일 미기록’으로 표시합니다. 신규 17개 응답 완료 시점을 저장하고 한국 시간으로 표시합니다.
- 별도 PrintReport가 같은 생성 데이터를 이용합니다. ‘인쇄 / PDF 저장’은 브라우저 인쇄 창을 열며 저장 대상을 사용자가 선택합니다.
- 표준 샘플은 A4 2쪽, 긴 보고서는 강제 페이지 나눔을 완화해 글씨 축소나 잘림을 방지합니다.

## 개발자 미리보기
개발 모드에서는 `/report-preview` 경로를 사용할 수 있습니다. 프로덕션에서는 기본 404입니다. 필요할 때만 아래처럼 켭니다.

```bash
npm run build
ENABLE_REPORT_PREVIEW=1 npm start -- --port 3300
```

이 경로는 세 샘플 선택과 17개 JSON 응답 주입을 지원합니다. C는 both로 정규화하고 미응답·잘못된 값은 거부합니다. 실제 사용자 localStorage를 읽거나 변경하지 않습니다. 공개 사용자 흐름에 개발자 도구 링크를 추가하지 않았습니다.

```bash
npm test
CHROMIUM_PATH=/usr/bin/chromium REPORT_BASE_URL=http://127.0.0.1:3300 npm run test:report:e2e
```

## 검증 한계
브라우저·규칙·PDF 검증은 설문의 심리측정 타당도 검증이 아닙니다. 실제 사용자 최소 5명을 대상으로 한 이해도·과장 인식·활용 가능성 검증은 별도로 진행해야 하며, 이번 작업에서 실제 사람의 응답을 수집하지 않았습니다.
