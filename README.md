# 17job

17문항으로 감당하기 어려운 환경을 돌아보고, 작은 직무 미션으로 일을 탐색하는 한국어 MVP입니다. Next.js 16 / React 19 / TypeScript / Tailwind CSS 4 기반입니다.

## 실행

Node.js 22.18 이상이 필요합니다.

```bash
cd /workspace/17job
npm ci
npm run dev
```

프로덕션: `npm run build` 후 `npm start`. 기본 포트는 3000입니다. 잠금 파일을 포함하므로 반복 설치에는 `npm ci`를 사용합니다.

```bash
npm test
npm run typecheck
npm run build
```

순수 TypeScript 도메인 검증은 패키지 설치 없이 Node.js 내장 테스트 러너로 실행할 수 있습니다.

## 구현 범위

- 원문 17문항, A/B/둘 다 문제 없음, 이전·다음 이동 및 응답 수정
- 직접 선택한 부담 환경 분석. 반대 환경의 선호·능력 추론과 직무 적합도 점수 없음
- 5개 직무 후보, 각 직무의 대표 환경과 부담 응답의 접점 설명
- 서비스 기획자 서술형 체험 유지, 데이터 분석가의 쇼핑몰 결제 이탈 분석 4단계 체험 추가. 나머지 세 직무는 준비 중
- 데이터 분석가는 선택지와 판단 근거를 제출하고 단계별 자료 해설 확인. 선택·근거 수정 시 해당 직무의 이후 피드백만 무효화
- 설문 결과에 모든 부담 조건 태그와 즉시 시작할 작은 체험 안내
- 데이터 분석가에서는 행동 중심 체험명, 질문 보존, 단계별 관찰 안내, 과정별 자기보고 발견·다음 행동 기록
- 연습 CSV 및 개인 탐색 TXT 내려받기. 다음 행동 실행 여부는 사용자 직접 표시
- 기존 서비스 기획자의 흥미도·회고·직무 후보 흐름 유지
- 직무별 독립 기록·회고 이력, localStorage v2 복원과 기존 v1 데이터 자동 이전, 저장 불가 안내, 전체 초기화

직무 환경 데이터는 대표적인 예시이며 조직별 실제 근무 조건을 보장하지 않습니다. 추천은 직무 적합도 판정이 아닙니다. UX 디자이너·콘텐츠 마케터·운영 매니저는 소개만 제공하며 실제 미션은 준비 중입니다. 새 체험은 한 번에 하나씩 검토하며 추가합니다.

## 데이터와 AI 확장

설문은 `src/data/questions.json`, 직무·미션은 `src/data/jobs.json`, 응답별 확인 조건과 행동 탐색은 `src/data/exploration.json`에서 관리합니다. 로컬 피드백은 `src/lib/feedback.ts`의 `FeedbackProvider`를 구현합니다. 데이터 분석가 선택지에는 자료에 근거한 해설을 제공하고, 서술한 근거에는 키워드·길이에 따른 성찰 안내를 제공합니다. 자유 서술의 사실성·논리나 개인의 능력을 자동 판정하지 않습니다. 마지막 리뷰는 선택한 판단의 근거와 보완점, 실제 업무와의 차이, 후속 실습을 보여줍니다.

향후 OpenAI 연동은 서버 전용 Route Handler에 제공자를 구현해 비동기 인터페이스를 연결하세요. API 키는 서버에서만 읽고, 클라이언트에 포함하지 않습니다. 외부 전송 전 별도 사용자 안내·동의와 오류 처리, 요청 제한, 입력 검증이 필요합니다. 현재 외부 AI 호출과 개인정보 전송은 없습니다.

## 수동 사용자 흐름 검증

1. 홈에서 설문 시작 → 17개 응답. 미응답 시 다음 버튼이 비활성인지 확인합니다.
2. 결과가 선택한 A/B만 포함하고 둘 다 문제 없음은 부담에 포함하지 않는지 확인합니다.
3. 직무 목록에서 서비스 기획자 시작 → 각 미션에 판단 근거 제출 → 피드백 → 다음 단계.
4. 새로고침 시 답변과 진행 단계가 복원되는지 확인합니다.
5. 네 번째 미션 뒤 흥미도와 회고 저장 → 후속 후보 네 개와 체험 가능 여부 확인.
6. 이전 미션 수정 시 해당 단계 이후 피드백이 초기화되고 다시 제출해야 하는지 확인합니다.
7. 데이터 분석가의 4단계를 D → A → A → A로 진행해 3단계의 인과관계 단정에 보완 안내가 나오는지 확인합니다.
8. 두 직무 사이 이동·새로고침 시 선택, 초안, 피드백, 흥미도와 회고가 서로 섞이지 않는지 확인합니다.
9. 390px 및 PC 화면, 키보드 라디오 선택·포커스, 기록 초기화 취소·확인을 점검합니다.

## 자동 브라우저 검증

프로덕션 서버를 실행한 상태에서 별도 터미널로 아래를 실행합니다.

```bash
npx playwright install chromium
npm run test:e2e
```

시스템 Chromium을 쓰는 이 클라우드에서는 `CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e`로 실행합니다. 다른 포트를 쓸 때는 `BASE_URL`을 지정하세요. 테스트는 자체 브라우저 세션의 기록만 변경하며 화면 캡처는 `/tmp/17job-*.png`에 남깁니다.

기본 Turbopack이 이 환경의 내부 포트 제한에 걸려 개발·빌드 스크립트는 Next.js에서 지원하는 webpack 옵션을 사용합니다.

프로젝트 구조와 구현 계획은 [PLAN.md](PLAN.md)를 참고하세요. 이 작업은 기존 클라우드 환경 안에서 진행하며 별도 Git worktree를 만들 필요가 없습니다.


## 행동 중심 결과 확인
설문 결과에서 ‘문제의 성격’에 B를 선택했다면 해당 질문을 기록에 담고 ‘이 상황을 직접 확인해 보기’로 시작해 보세요. 체험 중 같은 질문이 유지되고 완료 후 흥미와 부담을 동시에 기록할 수 있습니다. 전체 흥미도를 선택하지 않아도 발견·다음 행동은 자동 저장됩니다. 탐색 기록 TXT는 브라우저에서만 생성하며 원격으로 업로드하지 않습니다.


검사 결과는 한 장 요약형입니다. 처음에는 선택한 모든 부담 조건 태그, 체험 시작만 보여주고, 전체 응답과 조건 설명 펼치기 영역은 제거했습니다. 조건은 설문 순서로 표시하며 중요도 순위가 아닙니다. 진행 중인 체험의 질문은 시작 당시 기준으로 유지합니다. 다른 조건을 고르더라도 기존 체험의 질문·답변을 자동으로 덮어쓰지 않습니다. 다음 행동을 바꿔도 각 행동의 메모와 실행 기록을 보존합니다.


## 배포 없이 실제 화면 테스트

`preview/17job-test.html`을 내려받아 일반 Chrome/Edge에서 열면 설치나 Vercel 로그인 없이 현재 화면을 누르며 테스트할 수 있습니다. React 화면·데이터·스타일·연습 CSV를 파일 안에 포함합니다. API·외부 폰트·원격 스크립트를 사용하지 않습니다. 개인 기록은 여전히 브라우저 로컬 저장이며 파일 안에 사용자 답변을 포함해서 배포하지 않습니다.

재생성: `npm run preview:file`. 이 명령은 Next.js 빌드 후 같은 Explorer 컴포넌트를 단일 HTML로 묶습니다. 서버 기능을 추가할 경우 이 미리보기에도 적용 가능한지 다시 확인해야 합니다.

관리형 브라우저가 file URL을 차단하면 로컬 HTTP로 검증할 수 있습니다. `python -m http.server 3200 --bind 127.0.0.1 --directory preview`로 시작하고, 별도 터미널에서 `CHROMIUM_PATH=/usr/bin/chromium PREVIEW_STANDALONE=1 BASE_URL=http://127.0.0.1:3200/17job-test.html npm run test:e2e`를 실행합니다. 이 주소는 내부 검증용이며 공유 가능한 공개 링크는 아닙니다.
